# מדריך בעלי מקצוע

חיפוש בעלי מקצוע **לפי תחום** (אינסטלציה, חשמל, שיניים…) ו**לפי שם**, שנבנה
אוטומטית מייצוא של קבוצת ווטסאפ שבה נשלחות המלצות ככרטיסי "איש קשר".

אתר סטטי לגמרי, בלי שרת ובלי תלויות. הכל רץ בדפדפן.

## הפעלה

**במחשב:** לפתוח את `index.html` בלחיצה כפולה. הכל עובד, כולל שמירת הנתונים.
אפשר גם להריץ שרת מקומי:

```bash
python3 -m http.server 8000
# ואז http://localhost:8000/pro-finder/
```

**בנייד (GitHub Pages):** Settings ← Pages ← Source: *Deploy from a branch*
← Branch: `main` / `(root)` ← Save. אחרי כדקה הכתובת היא
`https://<user>.github.io/<repo>/pro-finder/`.

כדאי להוסיף למסך הבית (שיתוף ← הוספה למסך הבית): זה נותן אייקון ופתיחה
במסך מלא, ובסאפארי זה גם פוטר את האתר מהמנגנון שמוחק אחסון של אתרים שלא
נכנסים אליהם כשבוע. בנוסף יש כפתור גיבוי ל-JSON במסך ההגדרות.

כדי שקובץ הייצוא יהיה זמין לבורר הקבצים בנייד: בווטסאפ ← ייצוא צ׳אט ←
ללא מדיה ← "שמירה בקבצים" (iOS) או שמירה ל-Drive / הורדות (אנדרואיד).

## פרטיות

**הנתונים לא יוצאים מהמכשיר.** קובץ הייצוא מפוענח בדפדפן, התוצאה נשמרת
ב-`localStorage`, ואין שום קריאת רשת. מספרי טלפון של אנשים אמיתיים **לא**
נשמרים בריפו, שהוא ציבורי. מי שמעתיק את התיקייה מקבל אפליקציה ריקה.

## איך להפיק את הקובץ

בווטסאפ: פרטי הקבוצה ← **ייצוא צ׳אט** ← **ללא מדיה**.

כרטיסי אנשי הקשר נכללים בייצוא גם בלי מדיה — ווטסאפ לא מתייחס אליהם כאל
מדיה כמו תמונה, וידאו או הודעה קולית — ולכן אין שום סיבה לגרור מאות
מגה-בייט של תמונות. אם בכל זאת כרטיס מופיע בצ׳אט בלי קובץ, האפליקציה
מציגה אזהרה מפורשת.

נתמכים גם ייצוא של אייפון (`[12/03/2024, 14:23:45] שולח: …`) וגם של אנדרואיד
(`12/03/2024, 14:23 - שולח: …`), וסדר התאריך (יום/חודש מול חודש/יום) מזוהה
אוטומטית מתוך הקובץ.

## איך נקבע התחום

לכל כרטיס איש קשר נאספים עד ארבעה אותות בלתי תלויים:

| אות | מקור | ודאות בסיס |
|---|---|---|
| שם הכרטיס | ה-vCard עצמו: `FN`, `ORG`, `X-WA-BIZ-NAME`, `X-WA-BIZ-DESCRIPTION` | 0.85 |
| כיתוב | הודעה של מי ששלח את הכרטיס, עד 3 הודעות ו-10 דקות ממנו | 0.60 |
| בקשת המלצה | הבקשה האחרונה בקבוצה שכוללת שם מקצוע | 0.80 / 0.60 / 0.35 לפי מרחק |
| תגובה | הודעה של מישהו אחר מיד אחרי הכרטיס | 0.30 |

הוודאות הסופית היא הגבוהה מביניהם, בתוספת 0.07 לכל אות נוסף שהסכים.
כששני תחומים קרובים זה לזה הרשומה מסומנת כדו-משמעית ונכנסת לתור הבדיקה.

**כל שיוך נשמר עם הראיה שלו** — הטקסט המקורי, השעה והשולח — ומוצג בכרטיס
תחת "למה סווג כך?". אפשר לתקן כל שיוך ידנית, והתיקונים שורדים ייבוא חוזר.

### מה המערכת לא יכולה לעשות

ייצוא ווטסאפ **לא שומר מי הגיב למי**. אין בקובץ שום מטא-דאטה של ציטוט או
תגובה, ולכן אי אפשר לדעת בוודאות לאיזו בקשה כרטיס מסוים עונה. הקישור נעשה
לפי סמיכות בזמן ובסדר ההודעות, וזו הסיבה שכל שיוך מלווה בראיה גלויה.

שני כללים מיוחדים מטפלים במקרים שההיוריסטיקה הפשוטה נכשלת בהם:

- **מחפשים את הבקשה האחרונה, לא את ההודעה האחרונה.** כרטיס של שיננית יכול
  לשבת באמצע שרשור על סדנאות בישול, כשהבקשה הנכונה היא חמש הודעות אחורה.
- **שם איש הקשר עוצר את הסריקה.** אם הודעה סמוכה מזכירה את שם איש הקשר,
  זו ההודעה שהכרטיס עונה לה, ואין להמשיך אחורה לבקשה ישנה יותר.

## כלים

```bash
node tools/selftest.js                    # בדיקות על מקרי הקצה
node tools/extract-cli.js <ייצוא.zip>     # הרצת אותו מנוע בלי דפדפן
node tools/extract-cli.js <ייצוא.zip> --evidence
```

`extract-cli.js` לא כותב קבצים, רק מדפיס. שימושי כדי לאמת את הסיווג מול
הצ'אט המקורי לפני שמסתמכים עליו.

## מבנה

| קובץ | תפקיד |
|---|---|
| `js/util.js` | ניקוי סימני כיווניות, נרמול טלפון ישראלי |
| `js/professions.js` | טקסונומיית התחומים והתאמת מילות מפתח בעברית |
| `js/vcard.js` | פענוח `.vcf`, כולל החריגות של ווטסאפ |
| `js/zip.js` | קריאת ZIP דרך `DecompressionStream`, בלי ספריות |
| `js/whatsapp.js` | פענוח קובץ הצ'אט להודעות |
| `js/classify.js` | איסוף האותות, ציון הוודאות והמיזוג לאנשים |
| `js/store.js` | `localStorage` והתיקונים הידניים |
| `js/app.js` | ניתוב ותצוגה |
| `manifest.webmanifest`, `icon.svg`, `apple-touch-icon.png` | הוספה למסך הבית בנייד |

כל מודול נטען גם בדפדפן וגם ב-`require` של Node, כדי שה-CLI והאתר ירוצו על
אותו מנוע בדיוק ולא ייפרדו עם הזמן.
